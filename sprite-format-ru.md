# Формат файла разметки спрайтов

Редактор сохраняет разметку в один JSON-файл: `<ИМЯ>.json` в папке данных
игры `game_data/` (сам, после каждого изменения) или кнопкой «JSON ⭳». В нём
то, чего нет в самих картинках: базовая точка каждого кадра, теневые маски
столкновений и именованные точки привязки. Сами картинки в файл не входят:
кадр ссылается на свой PNG по имени файла.

Здесь описано, что значит каждое поле. По этому документу конвертер движка
(`components/dgx-ge/tools/dgx_ge_pack.py`) читает файл. Как пользоваться
редактором, описано отдельно, в [usage-ru.md](usage-ru.md). Примеры взяты из
`examples/walk.json`.

## Коротко

- Файл — JSON: список описаний масок и список наборов кадров.
- У каждого кадра есть базовая точка (`origin`) — в пикселях картинки от её
  левого верхнего угла. Всё остальное (маски, точки, холст) — от базовой
  точки.
- Маска — 1-битный прямоугольник, строки битов записаны шестнадцатеричными
  цифрами, старший бит слева.
- Кадр без масок получает маску по умолчанию: свои непрозрачные пиксели под
  индексом `defaultMask` набора.
- Зеркалирование — вокруг базовой колонки: x переходит в −x.
- У набора могут быть анимации (`animation`): скрипты кадров и правила
  переходов, то же, что текст `.anim` движка.
- У файла могут быть сцены (`scenes`): уровни из слоёв с картинками,
  персонажами, зонами, сетками плиток, выходами и связями.
- У файла могут быть поля игры целиком: числа игры (`game`), константы
  пакета (`constants`), таймеры (`timers`), звуки (`sounds`), показы
  (`shows`), погоня (`chases`), вырезки (`crops`) — то, что упаковщик берёт
  вызовами `add_game`, `add_constants`, `add_timer`, `add_sound`,
  `add_show`, `add_chase`, `add_crop`.

## Понятия

- **Картинка** — PNG одного кадра: прямоугольник `width` × `height`
  пикселей с палитрой.
- **Кадр** — картинка вместе с разметкой: базовой точкой, масками и
  точками привязки.
- **Набор** — кадры одного персонажа или предмета, например все кадры
  принца. Кадры набора размечаются вместе и сравниваются друг с другом.
- **Базовая точка** — пиксель, которым спрайт ставится на место в игре.
  Обычно это пиксель у ног, но может лежать и вне картинки.
- **Холст** — прямоугольник набора, общий для всех его кадров. Кадры
  ставятся на него базовыми точками в одно и то же место, поэтому холст
  охватывает все кадры набора сразу. Его размер — наибольший размер спрайта
  набора.
- **Маска** — 1-битная «тень» кадра для столкновений. Она лежит на холсте
  отдельно от картинки: может быть меньше картинки, больше неё, выходить за
  её края, но не за края холста.
- **Точка привязки** — именованный пиксель кадра, к которому цепляется
  другой спрайт.

Картинка и холст — разные прямоугольники. Картинка у каждого кадра своя и
своего размера, холст один на набор и не меньше любой картинки набора:

```
   холст набора (canvas): left, top — его левый верхний пиксель от базовой точки
   ┌──────────────────────────────────────────────┐
   │                                              │
   │          ┌────────────┐                      │
   │          │            │                      │
   │          │  картинка  │▒▒▒▒▒▒▒ ← маска клинка:│
   │          │  кадра     │▒▒▒▒▒▒▒   за картинкой,│
   │          │  (PNG)     │          но в холсте │
   │          │            │                      │
   │          └─────■──────┘                      │
   └────────────────┼─────────────────────────────┘
                    базовая точка (0, 0)
```

У другого кадра того же набора картинка другого размера и стоит иначе, но
её базовая точка попадает в то же место холста.

## Система координат

- Ось X идёт вправо, ось Y — вниз. Единица — пиксель кадра.
- **Базовая точка** кадра (`origin`) задаётся в пикселях картинки от её
  левого верхнего угла. Это единственные координаты в файле, заданные от
  угла картинки.
- **Всё остальное** — маски, точки привязки, холст — отсчитывается от
  базовой точки: пиксель базовой точки имеет координаты (0, 0). Пиксель
  картинки (px, py) имеет координаты (px − origin.x, py − origin.y).
  Поэтому слева и сверху от базовой точки координаты отрицательные.
- Строка базовой точки — **базовая линия**: ноги стоят на ней, то есть
  нижний край строки y = 0 — это пол. Столбец базовой точки — **базовая
  колонка**: вокруг неё спрайт зеркалится (см. «Зеркалирование»).
- Пока кадр не размечен, редактор ставит базовую точку
  в левый нижний пиксель картинки: `origin = (0, height − 1)`.

Пример — кадр `walk-1.png` 8 × 14 с `origin` (3, 13). Его левый верхний
пиксель имеет координаты (−3, −13), правый нижний — (4, 0), базовая точка —
пиксель картинки (3, 13), то есть (0, 0).

## Общий вид

```json
{
    "format": "dgx-ge-sprites",
    "formatVersion": 1,
    "name": "example",
    "masks": [
        { "index": 1, "name": "body", "color": "#e04040" },
        { "index": 2, "name": "blade", "color": "#3070e0" }
    ],
    "sets": [
        {
            "name": "walk",
            "defaultMask": 1,
            "canvas": { "left": -6, "top": -15, "width": 19, "height": 16 },
            "frames": [
                {
                    "image": "walk-1.png",
                    "width": 8,
                    "height": 14,
                    "origin": { "x": 3, "y": 13 },
                    "masks": {
                        "1": { "x": -3, "y": -13, "width": 7, "height": 14,
                               "rows": ["38", "7c", "7c", "38", "7c", "fe", "fe", "fe", "38", "38", "28", "28", "28", "6c"] }
                    },
                    "points": { "hand": { "x": 3, "y": -6 } }
                },
                ...
            ]
        }
    ]
}
```

## Поля файла

| Поле | Смысл |
| --- | --- |
| `format` | Тип файла, всегда `dgx-ge-sprites`. По нему конвертер узнаёт, что это файл этого редактора |
| `formatVersion` | Версия формата, целое число. Растёт, когда файл нового формата нельзя прочитать как старый; новые необязательные поля версию не меняют. Сейчас 1 — формат, описанный здесь |
| `name` | Название разметки, оно же имя файла при сохранении |
| `masks` | Описания масок: какие индексы есть, как они называются, каким цветом показаны. Порядок — по возрастанию индекса |
| `meets` | Необязательное. Какие маски встречаются, текст (см. «Какие маски встречаются»). Нет поля — умолчания движка |
| `sets` | Наборы кадров — виды (в редакторе Kinds): у набора могут быть и кадры, и анимация, и только одно из них |
| `palettes`, `screen`, `tilesets`, `scenes`, `styles`, `dialogs` | Необязательные: палитры, экран и сцены, стили и тексты диалогов — свои разделы ниже |
| `game`, `constants`, `timers`, `sounds`, `shows`, `chases`, `crops` | Необязательные: игра целиком — раздел «Игра целиком» |
| `graph`, `maps` | Необязательные: граф сцен — раздел «Граф сцен» |

Файл с другим `format` или с `formatVersion` больше известной редактор не
загружает. Конвертеру стоит поступать так же. Незнакомые поля редактор при
загрузке отбрасывает (кроме полей стилей диалогов: их он хранит как есть),
конвертер может их не замечать.

## Описание маски

```json
{ "index": 1, "name": "body", "color": "#e04040" }
```

| Поле | Смысл |
| --- | --- |
| `index` | Индекс маски — зона: тело, голова, клинок. Целое число, у разных масок разное. Что значит индекс, решает логика игры; движок только сообщает, маски каких индексов пересеклись |
| `name` | Имя для человека. Движку не нужно, но конвертер может выдать его как имя константы индекса |
| `color` | Цвет маски в редакторе, `#rrggbb`. Движку не нужен |

Описания общие для всех наборов: индекс 1 значит одно и то же во всём
файле. Сколько всего индексов, формат не ограничивает. Редактор даёт
индексы от 0 до 15 (`MaskLimit` в `Store.js`, 16 масок); это его настройка,
а не часть формата. 0 — обычный индекс, «нет маски» он не означает.

Какие маски действуют в каком кадре анимации («клинок опасен только на
кадрах удара») — дело скрипта анимации: команда `masks` в анимациях набора
(см. «Анимации набора»). Маски кадров здесь — только то, как они нарисованы.

## Какие маски встречаются

У тела столкновений в движке есть **хозяин** (части одного целого — рука и
меч в ней — не встречаются никогда) и **сторона** (брошенный камень
остаётся на стороне бросившего). Пара масок двух тел одной стороны
проверяется, только если она перечислена как `own`, тел разных сторон —
только если перечислена как `foreign`.

Поле `meets` — текст, пара на строку, `#` — комментарий до конца строки:

```
foreign BLADE BODY    # удар достаёт
foreign BLADE PARRY
own STONE BODY        # брошенный камень может упасть на бросившего
```

- Строка — `own|foreign <маска> <маска>`. Маска — имя (`name` из `masks`
  по правилу имён пакета: буквы и цифры остаются, остальное `_`, заглавные;
  `"the blade"` — это `THE_BLADE`; без имени — `MASK_<индекс>`) или индекс
  0…15. Слово из одних цифр — всегда индекс. У двух масок одно имя —
  имя означает последнюю из них.
- Пара симметрична: `a b` то же, что `b a`. Пары, которой нет, не
  встречаются. Одна пара дважды в одной матрице — ошибка.
- Нет поля — умолчания движка: own — ничего, foreign — каждая пара. Пустой
  текст — не встречается ничего.
- Ошибки упаковщика (`add_sprites`): неизвестная маска, строка не того
  вида, пара дважды.

В пакете (DGPK v4) это таблица 64 байта: 16 строк own по 16 бит, затем 16
строк foreign; бит `b` строки `a` — маски `a` и `b` встречаются.

Редактор хранит текст как есть, с комментариями (сетка own/foreign под
таблицей масок пишет и убирает строки). При переименовании, смене индекса
и удалении маски он правит её слова в тексте, строки удалённой маски
убирает.

## Набор

| Поле | Смысл |
| --- | --- |
| `name` | Имя набора, у разных наборов разное. Картинки набора — файлы из одного каталога; редактор ищет картинку по имени набора и имени файла |
| `defaultMask` | Индекс маски по умолчанию: её получает кадр, у которого нет ни одной маски, см. «Нарисованная, пустая, отсутствующая». `null` или нет поля — маски по умолчанию нет. Новый набор в редакторе получает 1 |
| `canvas` | Холст набора: `left`, `top` — его левый верхний пиксель от базовой точки, `width`, `height` — размер в пикселях |
| `frames` | Кадры, по имени файла по возрастанию (числа в имени сравниваются как числа: `walk-2` раньше `walk-10`) |
| `animation` | Необязательное. Анимации набора: скрипты кадров, события, группы, правила переходов, см. «Анимации набора». Нет поля — анимаций нет |
| `facesLeft` | Необязательное, `true`: картинки набора смотрят влево («вперёд» — влево); только для показа в редакторе |
| `frameTable` | Необязательное: таблица кадров по номерам для `frame N` — `[{set, image, dx, dy} | null, …]`, индекс — номер; картинка из любого набора, `dx` — вперёд, `dy` — вниз от персонажа; `null` — номер без картинки. Только для проигрывателя редактора: игра, что рисует номера сама (PoP), держит свою таблицу |

Холст охватывает всё, что есть в кадрах набора: пиксель базовой точки,
картинки, маски и точки привязки. У `walk` холст начинается в 6 пикселях
левее и 15 выше базовой точки, то есть занимает x от −6 до 12 и y от −15
до 0.

Конвертеру холст нужен как наибольший размер спрайта набора и как граница,
за которую ничего в кадрах не выходит. Обрезать маски по содержимому
конвертер может сам. Порядок кадров в `frames` — только порядок имён
файлов, а не порядок анимации.

## Кадр

| Поле | Смысл |
| --- | --- |
| `image` | Имя файла PNG без каталога |
| `width`, `height` | Размер картинки в пикселях, каким он был при разметке. По нему конвертер может проверить, что разметка от этой картинки |
| `origin` | Базовая точка в пикселях картинки от её левого верхнего угла. Может лежать и вне картинки |
| `masks` | Маски кадра. Ключ — индекс маски строкой (`"1"`), значение — маска. Нарисованы могут быть не все маски из `masks` файла |
| `packName` | Необязательное: своё имя картинки в пакете (`DAGGER`), по правилу имён (буквы и цифры, остальное `_`, заглавные); нет — `<НАБОР>_<ФАЙЛ>`. Так её называют анимации, плитки и стили |
| `points` | Точки привязки. Ключ — имя точки, значение — `{x, y, z}`: место от базовой точки и сторона тела, см. «Точки привязки» |

Когда в редакторе сдвигают базовую точку, маски и точки сдвигаются вместе с
картинкой: на её пикселях они остаются там же, а их координаты в файле
меняются на сдвиг с обратным знаком.

## Маска кадра

```json
"1": { "x": -3, "y": -13, "width": 7, "height": 14, "rows": ["38", "7c", ...] }
```

Маска — 1-битная картинка в прямоугольнике.

| Поле | Смысл |
| --- | --- |
| `x`, `y` | Левый верхний пиксель прямоугольника маски от базовой точки |
| `width`, `height` | Размер прямоугольника |
| `rows` | `height` строк сверху вниз. Строка — шестнадцатеричные цифры, `ceil(width / 4)` штук, цифра — 4 пикселя, старший бит — левый. Лишние биты последней цифры — нули |

Пиксель (c, r) прямоугольника, где c — столбец, а r — строка, считая от 0,
задан битом `(int(rows[r][c // 4], 16) >> (3 - c % 4)) & 1`. Его координаты
от базовой точки — (x + c, y + r).

Вся маска кадра `walk-1` (тело, индекс 1): `x` −3, `width` 7, поэтому
столбцы прямоугольника — это x от −3 до 3. Восьмой бит каждой строки —
дополнение до целой цифры, он всегда 0.

```
  y   rows  биты      x: -3 -2 -1  0  1  2  3
-13   "38"  0011 1000      ·  · ██ ██ ██  ·  ·
-12   "7c"  0111 1100      · ██ ██ ██ ██ ██  ·
-11   "7c"  0111 1100      · ██ ██ ██ ██ ██  ·
-10   "38"  0011 1000      ·  · ██ ██ ██  ·  ·
 -9   "7c"  0111 1100      · ██ ██ ██ ██ ██  ·
 -8   "fe"  1111 1110     ██ ██ ██ ██ ██ ██ ██
 -7   "fe"  1111 1110     ██ ██ ██ ██ ██ ██ ██
 -6   "fe"  1111 1110     ██ ██ ██ ██ ██ ██ ██
 -5   "38"  0011 1000      ·  · ██ ██ ██  ·  ·
 -4   "38"  0011 1000      ·  · ██ ██ ██  ·  ·
 -3   "28"  0010 1000      ·  · ██  · ██  ·  ·
 -2   "28"  0010 1000      ·  · ██  · ██  ·  ·
 -1   "28"  0010 1000      ·  · ██  · ██  ·  ·
  0   "6c"  0110 1100      · ██ ██  · ██ ██  ·   ← базовая линия
```

Голова — строки −13…−9 — стоит над базовой колонкой x = 0, ноги — на
базовой линии y = 0.

Маска может выходить за картинку — например, маска клинка шире
нарисованного лезвия, — но не за холст. Редактор хранит маску обрезанной
по её пикселям, но конвертеру на это полагаться не нужно: прямоугольник
может быть и больше пикселей.

### Нарисованная, пустая, отсутствующая

- **Маска есть и в ней есть пиксели** — зона этого индекса в кадре такая,
  как нарисована.
- **Маска есть, но пустая**: `{"x": 0, "y": 0, "width": 0, "height": 0,
  "rows": []}` («Clear» в редакторе). Маска нарисована, и в ней ничего нет:
  в этом кадре зона этого индекса ни с чем не пересекается.
- **Маски нет** («None» в редакторе). Этот индекс в кадре не нарисован.
- **У кадра нет ни одной маски** (`masks` пуст): действует маска по
  умолчанию — непрозрачные пиксели картинки, то есть все пиксели с
  ненулевым индексом палитры. Её индекс — `defaultMask` набора: что значит
  индекс, знает игра, а у разных наборов зона «тело» может иметь разный
  индекс. Если `defaultMask` равен `null` или его нет, маски по умолчанию
  нет, и кадр без масок ни с чем не сталкивается — так удобно для
  декораций.

Маска по умолчанию действует, только пока у кадра нет **ни одной** маски.
Стоит нарисовать в кадре любую маску, хоть одну точку другого индекса, —
маски по умолчанию у кадра больше нет. Поэтому в редакторе сначала нажимают
«Fill»: маска записывается явно, равной непрозрачным пикселям картинки, и
дальше её правят кистью.

## Точки привязки

```json
"points": { "hand": { "x": 7, "y": -7, "z": 1 } }
```

Именованная точка кадра: `x`, `y` — от базовой точки, `z` — что к ней
прикреплено, рисуется перед телом владельца (`z` > 0) или за ним (`z` < 0);
числа — как `z` дочернего элемента в движке: дети между собой — по `z`, 0 не
бывает, разумные значения −8…7. Нет поля `z` — 1, перед телом. `z` свой в
каждом кадре (рука на замахе — за корпусом). При отражении спрайта `z` не
меняется. К ней цепляется дочерний спрайт:
меч в руке, поднятый камень. Имя — любая строка; одна и та же точка в разных
кадрах называется одинаково (редактор подсказывает имена, которые уже есть в
наборе). В одних кадрах точка может быть, в других — нет. Точка — это
пиксель, как и базовая точка.

## Анимации набора

Поле `animation` набора — это анимации движка: скрипты кадров и машина
состояний переходов между ними. Оно говорит то же, что текст на языке
`.anim` ассемблера движка (`components/dgx-ge/tools/dgx_ge_anim.py`, язык
описан в начале файла), только в виде JSON. Редактор пишет его этим текстом
в файл `<НАБОР>.anim` рядом с JSON (сам, в папку игры, или кнопкой «Export
.anim ⭳» у вида) и читает из него; ассемблер даёт по записанному тексту тот
же байт-код, что по исходному. Упаковщик (`add_sprites`) берёт анимации из
файлов `<НАБОР>.anim`, а не из этого поля.

Поле необязательное, и старый читатель файла его просто не замечает,
поэтому `formatVersion` остаётся 1.

Пример из `examples/walk.json` (целиком тот же текст — `examples/walk.anim`):

```json
"animation": {
    "events": ["walk", "stop", "turn"],
    "params": [{ "name": "action", "value": 0 }],
    "groups": [{ "name": "still", "scripts": ["stand", "turn"] }],
    "scripts": [
        { "name": "stand", "lines": [
            { "op": "set", "param": "action", "value": 0 },
            { "op": "frame", "image": "walk-1.png", "ms": 200 },
            { "op": "hold" }
        ] },
        ...
    ],
    "rules": [
        { "event": "walk", "source": "still", "to": "walk", "when": "end" },
        { "event": "stop", "source": "walk", "to": "stand", "when": "branch" },
        ...
    ]
}
```

| Поле | Смысл | В тексте `.anim` |
| --- | --- | --- |
| `events` | События, на которые набор отвечает правилами. Их номера в пакете общие (см. ниже) | `event walk, stop, turn` |
| `defines` | Именованные константы: имя и значение — число или выражение из чисел и прежних `define`. Порядок важен: константа видит только те, что выше | `define gravity 3 * 12 * 12` |
| `questions` | Необязательное. Вопросы игре: список имён; в тексте — `game имя имя …` (можно несколькими строками, до 255), в выражениях — `game.имя`: ответ игры в момент шага (`dgx_ge_expr_ask`; без функции — 0). Номер — порядок в списке; в заголовке `<PREFIX>_<ВИД>_GAME_<ИМЯ>`. Имя не совпадает с define, параметром, таблицей и словами языка; `game` — слово языка |
| `tables` | Необязательное. Таблицы констант: список `{name, values}`, `values` — целые числа 16 бит. В тексте — `table имя v1 v2 …`, в выражениях — `имя[индекс]` (0 вне таблицы). Только у анимаций: не у кусков плиток и не у диалогов. Имя не совпадает с define, параметром, функцией и словами языка (`t`, `now`, `vx`, `vy`, `x`, `y`, `its`, `and`, `or`, `not`) |
| `params` | Параметры персонажа: имя и начальное значение −32768…32767 (число или выражение из чисел и `define`). Порядок — их номера, по которым игра их читает. Во время игры параметр держит 32 бита | `param action 0` |
| `pockets` | Необязательное. Сколько мест для вещей у персонажа, 0…255 (число или `define`); нет — карманов нет | `pockets 6` |
| `stack` | Необязательное. Сколько вещей этого вида помещается в одно место кармана, 1…255; нет — 1 | `stack 10` |
| `groups` | Группы: имя и явный список скриптов. Скрипт может быть в нескольких группах, но в одной — один раз | `group still: stand, turn` |
| `scripts` | Скрипты по порядку: это их номера в байт-коде, и скрипт, дошедший до конца, продолжается в следующий по этому порядку | `script stand` и строки под ним |
| `rules` | Правила переходов | `on walk: still -> walk end` |

Имена скриптов, меток, событий, групп и параметров — буквы, цифры и `_`;
скрипты и метки не повторяются, параметры тоже.

**События общие для пакета.** Упаковщик держит один список имён событий:
одно имя получает один номер во всех блобах пакета, новые имена
добавляются в конец, всего их не больше 255. Матрица блоба шириной в
события пакета, известные к моменту его сборки. Событие, которое шлют
`hit … event`, `recoil` или `contact on`, этот набор может не объявлять:
оно становится событием пакета (`hit 5 on 6 event taken` руки говорит
горшку `taken`; горшок объявляет `event taken` и держит правило). Правило
`on e:` требует `event e` в своём наборе. Редактор о таком событии
предупреждает, если его не объявляет ни один набор (для `event`) или сам
набор (для `recoil` и `contact`: их получает сам персонаж). Отдельно, без
пакета, такой `.anim` не собирается — `assemble(text)` нумерует события
сам и требует объявления. В заголовок пакета идут и `<PREFIX>_EVENT_<ИМЯ>`
(общие), и `<PREFIX>_<АНИМАЦИЯ>_EVENT_<ИМЯ>`.

**Параметр** — число, которое каждый актёр хранит у себя: жизни, «что он
делает». Движок только хранит его и даёт скриптам менять (`set`, `add`),
смысл знает игра. При старте актёра параметры получают начальные значения,
между скриптами сохраняются. Ассемблер принимает до 255 параметров. Исполнитель движка держит у актёра
`DGX_GE_ANIM_PARAMS` и блоб с большим числом не откроет; сборка игры берёт
это число из заголовка пакета (`dgx_ge_params_of_pack`): столько, сколько у
самой жадной анимации пакета, по 8 байт на параметр у каждого актёра.

### Строки скрипта

Скрипт — список `lines`, по строке языка на элемент, в том же порядке:

| `op` | Поля | В тексте `.anim` |
| --- | --- | --- |
| `frame` | картинка (см. ниже), `ms` 1…65535, `at` `{x, y}` −128…127 — необязательно; или `expr` — картинка выражением, и `ms`; или `none: true` — ничего не показывать это время (упаковщик пишет картинку 0xFFFF, у персонажа картинка −1: спрятан; скрипт без кадра оставляет прежнюю картинку) | `frame WALK_WALK_1 200ms at 2, -1`, `frame (DAGGERS_1 + min(amount, 10) - 1) 1000ms`, `frame none 100ms` |
| `keep` | ничего: мир держит персонажа, пока он в этом скрипте | `keep` |
| `timer` | `action`: `start`, `stop`, `hold` (приостановить), `go` (продолжить); `name` — таймер игры (те же имена, что у `timer(ИМЯ)`); игре сообщается, что сделано | `timer start clock` |
| `draw` | `point` — точка, как у `carry`; `kind` — вид вещи, как у `shoot`: из карманов в руку | `draw hand SWORD` |
| `stow` | `point`: то, что держит точка, — в карманы | `stow hand` |
| `dx`, `dy` | `value` −128…127 | `dx 2` |
| `set` | `param` — имя параметра, `value`: присвоить. Постоянное −32768…32767 хранится в шаге, дальше, до ±2²⁴ (точно во float), — выражением; выражение округляется, не число — 0 | `set action 1` |
| `add` | `param`, `value` (как у `set`): прибавить; значение упирается в границы 32 бит | `add hp -1` |
| `signal`, `sound` | `value` 0…255 | `signal 3` |
| `velocity`, `accel` | `x`, `y` −32768…32767 | `velocity 40 0`, `velocity 40, -power + 10` |
| `path` | `x`, `y` — выражения от `t`: положение по формуле, см. ниже | `path x: 40*t, y: 3*sin(t*6)` |
| `contact` (маска) | `mask` 0…15 (число, `define` или имя маски пакета); `side` — `inside`, `below`, `above`, `left`, `right`, `beside` (слева или справа), `front`, `back` (по взгляду), `any`, или `none` — больше не следить; `within` 0…255 (1 — по умолчанию; 0 — только `inside`); `event` — событие себе в момент касания чего-то сплошного этой стороной; `off` — событие, когда перестала касаться; хотя бы одно из них; `first` 1…255 (только с `off`; `first within 8` в конце) — если в начале слежения (или при первом взгляде с местностью) в пределах стольких точек с этой стороны ничего нет, `off` приходит сразу: кадр, которому нужен пол, начат над пустотой (CONTACT_FIRST 43: байты CONTACT_MASK и ещё один). Следить можно за двумя масками сразу | `contact 1 below on landed off fell`, `contact 1 below within 2 on landed`, `contact 10 below within 1 off fall first within 8`, `contact 1 off` |
| `contact` | `on`: `true` или `false` — искать касания местности (полы, стены описывает игра) или перестать; `event` — только при `on`, необязательное: событие, которое в момент касания получает сам персонаж (можно объявить и ниже) | `contact on`, `contact on landed`, `contact off` |
| `carry` | `point` — имя точки привязки кадров; картинка, как у `frame`: `image`, `number` или `name`, нет ни одного — `none`, ничего | `carry hand SWORD_3`, `carry hand none` |
| `shoot` | `point` — точка, как у `carry`; `kind` — вид снаряда: число 0…65535 или имя блоба пакета — анимации любого набора этого файла (`DAGGER`; упаковщик собирает анимации файла вместе, `add_anims`, порядок наборов не важен) или блоба, добавленного в пакет до файла; `x`, `y` — скорость, как у `release`, без них — `0 0` | `shoot hand DAGGER 220 0` |
| `tell` | `target` — кому: `holder` (тот, кто держит этого персонажа) с `event` — событием пакета, объявлять не нужно; или `cell` — клетка карты: `cell` (число или выражение, как считает `dgx_ge_cells`: у PoP (комната − 1)·30 + плита), `event`, `value` (число или выражение, 0 — нет) в её свой параметр; делает это игра (правила карты) | `tell holder drank_wine`, `tell cell 451, loosened, 3` |
| `press` | `cell` — число или выражение: кнопка в клетке карты нажата, как будто на неё наступили (её связи срабатывают); делает это игра | `press 720` |
| `clear` | `cell` — число или выражение: то, что лежит в клетке карты, исчезает; делает это игра | `clear 421` |
| `appear` | `kind` — вид (имя блоба пакета или число), `event` — событие пакета пришедшему, `x`, `y` — где (числа или выражения), `left` — лицом влево; `with` — необязательный список `{param, value}`: параметры пришедшего (по его нумерации), выражения; персонаж вида появляется в `x`, `y` и слышит `event`; где он живёт, решает игра | `appear KID, mouse_go, 200, 55, left`, `appear WOLF, born, x, y with age = 0` |
| `sense` | `target` — вид (имя или число), `any` (любой персонаж) или `cell` (непустая клетка); `radius` — число 0…65535 или выражение персонажа, которое считается на шаге (`30 - full / 4`: голодный чует дальше; флаг 4 шага, байты выражения после `where`); `seen` — необязательно, слово после радиуса: только тот, до кого взгляд дотягивается в радиусе сквозь завесы плиток (`veil`; флаг 2 шага); `where` — условие о найденном (необязательно), в нём `its.<параметр вида>`, `its.vx`, `its.vy`, `its.image`, `its.script`, `its.flip` у тел, `its.tile`, `its.mod`, `its.cell` у клеток; `into` — 1…3 имени параметров (или `_`): расстояние (−1 — никого), dx вперёд, dy; `copies` — `{param, value}`: что ещё списать с найденного | `sense WOLF within 80 where its.age > 3 into enemy, edx, edy, mate = its.cell`, `sense SHEEP within 120 seen into prey` |
| `steer` | `way` — `seek`, `flee`, `arrive`, `pursue`, `evade`, `wander`; `args` — выражения по порядку: скорость, сила[, радиус или разброс], затем dx, dy[, vx, vy] цели; у `wander` вместо цели `angle` — параметр угла (градусы, 0 вперёд, 90 вниз) | `steer seek 40, 10 to edx, edy`, `steer wander 20, 5, 30 angle heading` |
| `vanish` | без полей: игра убирает этого персонажа | `vanish` |
| `release` | `point` — имя точки привязки, как у `carry`; `x`, `y` — скорость, как у `velocity` (числа или выражения с параметрами и `define`, без `t`; x — вперёд), без них — `0 0` | `release grip 52, -110`, `release hand` |
| `hit` | `mask` — маска удара, `on` — список масок встреченного, по которым она бьёт (всё 0…15: числа, `define` или имена масок пакета); `damage` — урон, постоянное −32768…32767, нет — 0; `event` — событие встреченному, `recoil` — событие себе (имена событий, можно объявить и ниже) | `hit 2 on 1 3 damage 1 event hurt recoil parried` |
| `masks` | `indexes`: маски 0…15 — числа, `define` или имена масок пакета (см. ниже) | `masks 1 2`, `masks BODY TIP` |
| `flip`, `branch`, `hold` | — | `flip` |
| `goto` | `target`: скрипт или метка; `cond` — необязательное выражение: переход только там, где оно не 0, иначе дальше по скрипту | `goto walkcycle`, `goto noknife if count(DAGGER) == 0` |
| `label` | `name` | `label walkcycle` |

**Числа и выражения.** Каждое число строки (`ms`, `at`, `value`, `x`,
`y`, элементы `indexes`), начальное значение параметра и значение
`define` — либо целое число JSON, либо строка с выражением языка, как она
записана в тексте `.anim`: числа (и дробные), `+ - * /`, скобки, унарный
минус, `min(a, b)`, `max(a, b)`, `abs`, `sin`, `cos`, `sqrt`, `exp`,
`smoothstep(x)` (0 ниже 0, 1 выше 1, между ними плавно: `smoothstep((t - t0) / d)`),
`its.<имя>` — найденный шагом `sense` (только в его `where` и копиях);
`game.<имя>` — ответ игры на вопрос, объявленный строкой `game имя …` (в момент
шага; без функции игры — 0; не в `path` и не у плиток);
биты целых чисел (32 бита, отрицательные в дополнительном коде): `xor(a, b)`,
`bits(x)` (сколько единиц), `bit(n)` (2ⁿ, 0 вне 0…30), `field(x, first, count)`
((x >> first) & (2^count − 1)); таблицы констант анимации `имя[индекс]`
(целая часть индекса; вне таблицы — 0), имена
`define` и параметров, `t`; сравнения `< <= > >= == !=` и слова `and`, `or`,
`not` — они дают 1 или 0, так что годятся и в арифметику:
`velocity (hp > 0) * 40, 0`. В выражениях ещё `x` и `y` — где персонаж
сейчас, в точках сцены (`x` — не «вперёд», в отличие от `vx`); не для
констант и не в `path`; имена `x`, `y` заняты, как `vx`, `vy`, `now`, `t`.
Порядок от слабого к сильному: `or`, `and`,
`not`, сравнение, `+ -`, `* /`. Сравнения не идут цепочкой: `0 < x < 5` —
ошибка, пишите `0 < x and x < 5`. Где что можно:

- `ms`, `at`, `dx`, `dy`, `signal`, `sound`, `masks`, начальные значения
  параметров — только числа и `define`: ассемблер вычисляет их сразу и
  округляет до целого (половину — от нуля, как движок: −2,5 → −3);
- **константы пакета** (поле файла `constants`, «Игра целиком») стоят
  везде, где может стоять число, как `define`, данные до первой строки
  (`frame A TICK_MS ms`, `signal CLOCK_OUT`, `define tick 1000 / TICK_MS`).
  Своим `define`, `param`, `table` или `game` такое имя не назвать:
  «TICK_MS is a constant of the pack (83): not to be defined again»;
- **имена масок пакета** — только там, где ждут маску (`masks`, `hit … on
  …`, `contact <маска>`): то же имя, что в `meets` и в заголовке
  (`name` маски: буквы и цифры, остальное `_`, заглавными; маска без имени
  — `MASK_<индекс>`). `masks BODY TIP`, `hit TIP on BODY damage 1`,
  `contact FEET below on landed`. Имя даёт те же байты, что число. В других
  местах имя маски не число: `frame A BODY ms` — ошибка. Редактор хранит
  имя, как оно написано, и меняет его в скриптах, когда маску
  переименовывают или меняют её индекс (маска без имени);
- числа — десятичные или шестнадцатеричные (`0x80`); `%` — остаток (как
  `*` и `/`), `&` и `|` — побитовые И и ИЛИ над целыми (ниже `+` и `-`,
  выше сравнений: `mod & 0x7F == 2` — это `(mod & 0x7F) == 2`); `%`, `&`,
  `|` берут целые части (как `int32_t` движка), остаток — со знаком
  делимого, как в C (`-7 % 3` — `-1`); `rnd(n)` — кость игры, целое
  0…n: при сборке не вычисляется, поэтому в постоянных (`define`, `dx`…)
  его нет; проигрыватель редактора бросает её, как движок, от зерна 1;
- `c ? a : b` — `a`, если `c` не 0, иначе `b`; слабее всех остальных
  операций, справа налево (`a ? b : c ? d : e` — `a ? b : (c ? d : e)`);
  из постоянных вычисляется при сборке;
- `timer(ИМЯ)` — миллисекунды от запуска таймера игры с этим именем в
  момент шага, −1, если он не идёт (таймеры описывает игра: блоб
  `TIMERS`); как `count` — только у персонажа, не в `path`, не в
  постоянных; проигрыватель редактора таймеров не ведёт — у него −1;
- `axis(ИМЯ)` — ось геймпада игрока в момент шага (движок, ветка pad):
  `lx`, `ly`, `rx`, `ry` — стики, −1…1, `lt`, `rt` — курки, 0…1 (номер оси
  — порядок в этом списке; в блобе шаг 52 и байт номера). Только в скриптах
  анимаций: не в `path`, не в плитках, не в условиях диалогов, не в
  начальных значениях `param`; не сворачивается при сборке. Параметр или
  `define` с именем `axis` закрывает функцию. Проигрыватель редактора
  геймпада не знает — у него 0;
- `velocity`, `accel`, `set`, `add`, `release` — ещё и параметры актёра и `vx`,
  `vy` — его скорость в этот момент, точек сцены в секунду, x вперёд (с
  учётом разворота), и `now` — момент шага, секунды часов игры (дробное):
  такие выражения вычисляются на плате в момент шага (`set drunk now + 10`);
- `path` — параметры и `t`, но не `vx`, `vy`: скорость задаёт сама
  формула пути, и место зависело бы от частоты кадров.

Имена `t`, `vx`, `vy`, `and`, `or`, `not` и имена функций нельзя давать
`define` и параметрам. Выражение после вычисления должно попасть в границы своего поля. Строка
хранит текст как есть, поэтому `"accel 0 gravity"` остаётся
`{"op": "accel", "x": 0, "y": "gravity"}`, а не `432`.

**`carry`** — что персонаж держит: с этого шага в точке `point` своих кадров
он держит эту картинку (кадр меча под позу тела), пока следующий `carry`
той же точки её не сменит; смена скрипта и `masks` его не снимают. Точек
одновременно — две. Ставится она по правилу движка: точка картинки с тем
же именем (у меча `hand` — где его держат) — в точку носителя, без неё —
базовая точка картинки; отражается вместе с носителем; перед телом или за
ним — по `z` точки носителя. Имя точки — как в `points` кадров (или
заглавными, как в пакете); точки, которой нет ни у одного кадра, редактор
не знает и предупреждает: она должна быть в пакете.

**`contact`** — искать касания местности. С событием (`contact on landed`)
движок в момент касания уточняет этот момент, ставит персонажа на место
касания и посылает событие ему самому; дальше решает его матрица (горшок:
`flying` → `shatter`, камень: `flying` → `lying`). `contact off` события не
принимает. В блобе (DGAN 7) команда занимает 3 байта: событие `0xFF` —
без события. В проигрывателе местности нет: пока действует `contact on`
с событием, рядом с отметкой `contact` есть кнопка `touch → <событие>`,
она изображает касание.

**`carry` в DGAN 7** значит «чем показать то, что в точке, в этом кадре»
(кадр меча под позу руки); `carry <точка> none` — «его собственным
кадром». Держать может и сама игра (`dgx_ge_actor_hold`), и держимое
может быть отдельным персонажем со своими скриптами (меч, горшок);
отпускает его `release`. Байты не изменились; проигрыватель редактора,
где таких персонажей нет, рисует в точке картинку из `carry`, как раньше.

**`shoot <точка> <вид> [vx vy]`** — выстрел: из точки вылетает снаряд
этого вида со скоростью `vx`, `vy` (x — вперёд, знак разворота — в момент
шага). Вид — обычная анимация пакета, её **первый** скрипт говорит, что
это за снаряд: картинка (`frame`), падение (`accel`), маска (`masks`),
удары (`hit`). Игре сообщается `DGX_GE_ANIM_SHOOT` (значение — номер
точки), летит и попадает снаряд силами игры. Имя вида — имя блоба:
упаковщик собирает анимации наборов файла вместе (`add_anims`), поэтому
порядок наборов не важен; при переименовании набора редактор правит имя
вида в `shoot`. В
блобе (DGAN 9) скорость всегда записана выражениями. Проигрыватель
только пишет выстрел в журнал и строку состояния.

**Пометки скриптов** (только для проверок редактора; в JSON — `entry`,
`through` у скрипта, в `.anim` — комментарий строки `script`, ассемблер его
не видит): `entry` — скрипт запускает сама игра, предупреждение «никто не
ведёт в него» молчит; `through` — скрипт нарочно переходит в следующий
(`script run  # entry: the game starts it; through: goes on into the next on purpose`).

**Комментарии** текста `.anim` редактор хранит при том, к чему они
относятся: у define, параметра, таблицы, скрипта, строки скрипта, группы и
правила — `above` (список строк комментария над ним, без `#`) и `note`
(комментарий в конце его строки); у строк `event`, `game`, `pockets`,
`stack` — так же, в `heads` анимации (`{"event": {"above": [...], "note":
"..."}}`); комментарии после последней строки — `tail`. Все эти поля
необязательные; упаковщику они не нужны, он читает текст `.anim`.

**Карманы (DGAN 10).** `pockets N` и `stack N` — строки анимации до её
скриптов (в JSON — поля `pockets` и `stack` анимации): сколько у персонажа
мест для вещей и сколько вещей этого вида лежит в одном месте. `draw
<точка> <вид>` достаёт одну вещь вида из карманов в руку, `stow <точка>`
убирает то, что в точке, в карманы; `shoot` персонажа с карманами стреляет
из них (нет — нет и выстрела). Вид — как у `shoot`: число или имя
анимации набора этого файла (в любом порядке) или блоба, добавленного до файла. В выражениях `count(ВИД)` — сколько
вещей вида в карманах, `amount` — сколько вещей в самом персонаже (стопка
на полу); оба — только у персонажа (не в плитках, не в `path`, не в
`define`). `keep` — мир держит персонажа, пока он в этом скрипте (лежащий
горшок помнят, осколки — нет). `goto <куда> if <выражение>` переходит, только
если выражение не 0; иначе скрипт идёт дальше.

**Кадр выражением** `frame (<выражение>) <ms>`: картинка вычисляется в
момент шага; имена картинок пакета в нём — их номера (в JSON — поле `expr`
кадра вместо `image`/`number`/`name`; `at` у такого кадра нет). Выражение из
одних картинок и чисел ассемблер сворачивает в обычный кадр. Проигрыватель
редактора нумерует картинки, как упаковщик из этого файла (набор за
набором, кадр за кадром), `amount` у него 1, `count` — 0: карманов он не
ведёт, `draw` только пишет в журнал, `stow` убирает удерживаемое из точки.

**`tell holder <событие>`** — этот персонаж (горшок, который пьют)
просит игру послать событие тому, кто его держит (`DGX_GE_ANIM_TELL`).
Событие — общее для пакета (см. выше), объявляет его и отвечает на него
правилом держащий. В блобе (DGAN 8) 3 байта. Проигрыватель только пишет
команду в журнал: держащего в нём нет.

Когда `set` или `add` меняют значение параметра, игре сообщается номер
параметра (`DGX_GE_ANIM_PARAM`); проигрыватель пишет в журнал
`<параметр> = <значение>`.

**`release`** — отпустить то, что персонаж держит в точке `point`, со
скоростью `x`, `y` (пикселей в секунду, x — вперёд, знак разворота
учитывается в момент шага). Точка освобождается; если в ней что-то было,
игра узнаёт об этом (`DGX_GE_ANIM_RELEASE`, значение — номер точки) и сама
решает, что станет с предметом (брошенный камень летит). Если в точке
ничего нет — ничего не происходит. Картинку в точку может положить и сама
игра, без `carry`; `release` отпускает и её. В блобе скорость `release`
всегда записана выражениями, даже постоянная (DGAN 6). Проигрыватель
редактора освобождает точку и пишет в строку состояния, что и с какой
скоростью отпущено.

**`hit`** — удар. Строки `hit` подряд (комментарии и пустые строки между
ними не мешают) — один набор ударов; любая другая строка, метка или
`script` тоже, начинает новый. Удары действуют до следующего набора, до
команды `masks` или до входа в другой скрипт. Части после масок — в любом
порядке, каждая со значением; маски и урон — по одному слову (число или
имя `define`), без пробелов внутри.

**`path`** — положение по формуле: `t` — секунды с начала `path`, место —
точка, где он начался, плюс формула; `x` вперёд, по стороне на момент
начала. Действует до следующих `velocity`, `accel` или `path`; смены кадров
и скриптов его не прерывают; `dx`, `dy` сдвигают его начало; после смены
актёр продолжает со скоростью формулы (её производной).

Картинка кадра задаётся одним из трёх полей:

- `image` — имя файла кадра **этого набора**. В тексте `.anim` это имя
  картинки в пакете движка: `<НАБОР>_<ИМЯ ФАЙЛА БЕЗ РАСШИРЕНИЯ>`, всё, кроме
  ASCII-букв и цифр, заменено на `_`, затем заглавные буквы. Набор `walk`,
  файл `walk-1.png` → `WALK_WALK_1`. Конвертер называет картинки так же; два
  файла с одним таким именем — ошибка.
- `number` — номер, по которому кадр рисует сама игра (как у PoP), 0…65535.
- `name` — имя картинки пакета, которой нет среди кадров набора; пишется в
  текст как есть.

Команды `action N` в языке больше нет: это обычный параметр, `param
action 0` и `set action N`. Редактор, читая старый текст или старый JSON с
`action`, сам объявляет параметр `action` и пишет `set action N`.

Шаг анимации — команды до кадра включительно: команды делаются, когда
время предыдущего кадра вышло, затем кадр показывается `ms` миллисекунд.

### Правила

Правило — `{event, source, to, when}`: по событию `event` скрипт `source`
(или каждый скрипт группы `source`) переходит в скрипт `to`; `when`:

- `now` — сразу;
- `branch` — в ближайшей точке `branch` скрипта (или в его конце);
- `end` — там, где скрипт сам перешёл бы в другой (`goto`) или
  остановился (`hold`).

Правила только заполняют матрицу «скрипт × событие» — машину состояний.
Порядок правил ничего не значит, приоритетов нет, «все скрипты» (`*`) нет.
Два правила, дающие одной клетке разные ответы, — конфликт, ошибка; два
правила с одинаковым ответом — допустимо. Если имя группы совпадает с
именем скрипта, правило берёт группу.

## Сцены

Сцены — уровни игры, как их рисует `dgx_ge_scene.h` движка: слои сзади
вперёд, на слоях картинки и персонажи, плюс сетки плиток, зоны, входы,
выходы и связи. Они лежат на верхнем уровне файла, рядом с `sets`, и
ссылаются на кадры наборов по имени набора и имени файла. Все поля
необязательны: файл без них — файл без сцен (`formatVersion` остаётся 1).

```json
"screen": { "width": 320, "height": 240 },
"tilesets": [ {
    "name": "tiles", "cellWidth": 24, "cellHeight": 46,
    "tiles": [ {
        "name": "floor", "kind": 1,
        "solid": { "top": true, "left": false, "right": false, "bottom": false },
        "pieces": [ { "set": "walls", "image": "floor.png", "dx": 0, "dy": 0, "layer": "back", "key": 0 } ]
    } ]
} ],
"scenes": [ {
    "name": "room1", "width": 320, "height": 240, "background": "#000000",
    "layers": [ {
        "name": "back", "factor": 256, "order": "added", "visible": true, "locked": false,
        "objects": [
            { "type": "picture", "name": "", "set": "walls", "image": "torch.png", "x": 60, "y": 150, "key": 0, "flip": false, "clip": null },
            { "type": "actor", "name": "guard", "set": "guard", "script": "stand", "x": 160, "y": 182, "flip": true, "params": { "hp": 4 } },
            { "type": "zone", "name": "door", "kind": "exit", "x": 280, "y": 120, "width": 39, "height": 63 },
            { "type": "entry", "name": "from_left", "x": 20, "y": 182, "flip": false }
        ]
    } ],
    "grids": [ { "name": "grid", "tileset": "tiles", "x": 0, "y": 0, "cols": 13, "rows": 5,
                 "cells": [[0, 1, ...], ...], "mods": { "3,4": 2 } } ],
    "exits": [ { "edge": "right", "zone": "", "scene": "room2", "entry": "from_left" } ],
    "links": [ { "from": { "grid": "grid", "col": 3, "row": 4 }, "to": { "object": "door" } } ]
} ]
```

| Поле | Смысл |
| --- | --- |
| `screen` | Размер экрана устройства, пикселей; общий для всех сцен |
| `tilesets[].fields` | Имена битов модификатора и варианта клетки, см. «Поля набора плиток» |
| `tilesets` | Наборы плиток, общие для всех сцен |
| `scenes` | Сцены |

**Сцена.** `width`, `height` — размер в пикселях (до 32767); сцена размером
с экран — комната, больше — прокручивается. `background` — цвет фона в
редакторе. Координаты сцены — пиксели от её левого верхнего угла.

**Слой.** Слои рисуются по порядку списка, первый — самый дальний; их не
больше 8 (`DGX_GE_SCENE_MAX_LAYERS`). `factor` — как слой движется вместе с
окном сцены: 256 — вместе с ним, 128 — вдвое медленнее (дальний план), 0 —
стоит на месте (небо, панель); int16. `order`: `added` — картинки слоя
рисуются в порядке, в каком даны, `key` — по ключу, меньший раньше.
`visible` и `locked` — только для редактора.

У движка слой может быть «в пикселях экрана»
(`dgx_ge_scene_layer_pixels`): его объекты — не точки сцены, а пиксели
дисплея, рисуются в его разрешении поверх смасштабированного кадра
(диалоги, текст); `factor` не действует, детей нет. Картинки такого слоя
движок рисует в масштабе кадра: каждый пиксель картинки —
квадрат со стороной в масштаб (`dgx_ge_item_t.scale`). В JSON редактора
такого поля ещё нет; когда понадобится, оно будет `"pixels": true` рядом с
`factor` и `order`. Как упаковщик кладёт сцены в пакет — «Сцены в пакете»
ниже.

**Объекты слоя** (`type`):

| `type` | Поля | Смысл |
| --- | --- | --- |
| `picture` | `set`, `image`, `x`, `y`, `key`, `flip`, `clip` | Картинка: кадр набора, базовой точкой в `x`, `y`. `flip` — зеркально вокруг базовой колонки. `key` — для слоя с порядком `key`. `clip` — прямоугольник сцены `{x, y, width, height}`, вне которого картинка не рисуется, или `null` |
| `actor` | `set`, `script`, `x`, `y`, `flip`, `params` | Персонаж: где он появляется (базовой точкой), набор с анимациями, скрипт, с которого начинает, `params` — его начальные параметры вместо заданных в анимациях набора |
| `zone` | `kind`, `x`, `y`, `width`, `height` | Прямоугольник для логики игры; `kind` — слово, которое понимает игра (`exit`, `trap`…) |
| `entry` | `x`, `y`, `flip` | Точка входа: где окажется персонаж, придя в сцену, и куда он смотрит |

У всех объектов есть `name`. По имени игра знает объект из своего кода:
конвертер выдаёт имена константами (всё, кроме ASCII-букв и цифр, — `_`,
затем заглавные), поэтому в одной сцене два имени с одной константой —
ошибка. Картинке имя не обязательно.

**Сетка** (`grids`) — клетки плиток набора `tileset`, левым верхним углом в
`x`, `y` сцены, `cols` × `rows` клеток размером клетки набора. `cells` —
строки сверху вниз, в клетке 0 (пусто) или номер плитки с 1 (до 65535).
`mods` — модификаторы клеток для игры (состояние ворот, вид зелья…), 8 бит:
`"столбец,строка": число`, только у клеток, где он есть; нет — 0. По нему же
куски плиток выбирают картинку (`by_mod`) и сдвиг. `variants` — так же,
варианты оформления клеток, 32 бита (для `variant` кусков и выражений); нет
— 0.

**Поля набора плиток** (`fields`) — имена для битов модификатора и варианта
клетки: `{"middle_x": ["variant", 1, 3]}` — биты 1…3 варианта, `["mod", 7,
1]` — старший бит модификатора. В выражениях кусков (`dx`, `dy`, `pick`,
`color`, `when`) можно писать `mod`, `variant` и эти имена; поле — число
из своих битов, без знака. Персонажа у куска нет: `now`, `vx`, `vy` в них —
ошибка («now is of an actor, there is none here»), `t` — тоже. Поле нельзя
назвать `t`, `vx`, `vy`, `now`, `mod`, `variant`, именем функции или
`and`, `or`, `not`.

**Плитка** (`tiles` набора плиток) рисуется **кусками** (`pieces`). Так одна
клетка рисуется частями в разные слои (стена сзади персонажа, передняя
грань пола перед ним) и может залезать в соседние. `kind` — число игры.
`solid` — какие стороны плитки сплошные: сквозь них персонаж не проходит.
`closes` — необязательное, `{top, left, right, bottom}`: какие стороны
заканчивают открытое пространство, в котором персонаж виден (за ними его не
видно); нет поля — те же, что `solid`. Нужно, когда видимость не совпадает
со столкновением: сквозь дверной проём проходят, но справа он персонажа
скрывает. В PoP полы и стены закрывают снизу (потолок для стоящего ниже),
стены — слева, верх двери — справа. Имена плиток в наборе разные: по ним куски
смотрят на соседей.

`seen_as` — необязательное: имя другой плитки набора. Где условие соседей
(`around`) называет ту плитку, подходит и эта (опущенная плита видна как
пол: `"seen_as": "floor"`). Разрешается при упаковке, в блобе его нет.

`life` — необязательное (DGTS 8): имя анимации пакета (набора с
анимацией, по имени в пакете: `GATE`), которую клетка этой плитки играет
сама — ворота поднимаются и опускаются, пол осыпается, шипы выскакивают.
Её параметры: 0 — модификатор клетки, 1 — её плитка, дальше — свои.
Анимации наборов попадают в пакет раньше наборов плиток; анимации, которой
нет в пакете раньше, упаковщик не примет.

`bodies` — необязательное (DGTS 7): что в клетке сплошное, список
прямоугольников:

```json
"bodies": [{"dx": 0, "dy": -2, "w": 32, "h": 11, "when": "q < 39", "for": [1, 3]}]
```

Тело — прямоугольник от левого нижнего пикселя клетки, сдвинутого на `dx`,
`dy` (вверх — меньше нуля): `w` пикселей вправо и `h` вверх, считая сам
этот пиксель (по y — от `dy − h + 1` до `dy` от нижней строки клетки).
`dx`, `dy`, `w`, `h` — числа или выражения, как `dx` куска (`mod`,
`variant`, поля набора); `when` — необязательное выражение: тело есть только
там, где оно не 0 (постоянный 0 — ошибка). Тело с `w` или `h` не больше 0
ничего не останавливает. Тел у плитки не больше 255. Если тела заданы,
персонажа останавливают они, а стороны `solid` остаются только для условий
`around` кусков и для видимости (через `closes`); без тел действуют
стороны `solid` и полоса у края, как раньше. `for` — необязательное
(DGTS 8): маски, которые тело держит, список номеров
0..15 (`index` масок файла); нет или пусто — все маски. Движок,
спрашивая сетку маской (касание, стороны, выталкивание), видит только
тела, держащие её, поэтому у плитки могут лежать рядом тела по правилам
игры для людей (в PoP пол сдвинут на полклетки) и тела как нарисовано для
вещей (кувшин, осколки) — иначе вещи проваливались в щели людских тел.
В блобе — последние u16 тела, биты масок (0 — все), размер тот же.
Редактор показывает тела красными рамками на сцене (флажок Bodies; рядом
выбор «for …» — только тела, держащие эту маску, как их видит движок;
тело не для всех масок — пунктиром) и в миниатюре плитки (для `mod` 0 и
`variant` 0) и правит их в свойствах плитки; проверка: номера 0..15,
повторы, маски, которых нет в файле.

`veil` — необязательное (движок, ветка life): завеса, 0…7 — сколько стоит
взгляд сквозь плитку для `sense … seen`: 0 — прозрачна (нет поля — 0),
1…6 — точка сквозь неё стоит 2…7 точек радиуса, 7 — сквозь неё не видно.
В блобе — старшие 3 бита байта `closes`, версия та же. Своя клетка ищущего
не считается.

`opening` — необязательное (DGTS 9, движок, ветка door-stairs): проём
плитки, `{"dx", "dy", "w", "h", "when"}` — прямоугольник, как тело, с теми
же выражениями, но без `for` (упаковщик и проверка редактора его
отвергают). Проём не сплошной: через него виден персонаж, ушедший внутрь
плитки (вверх по лестнице двери выхода). В блобе — запись сразу после тел,
не в их числе; бит 16 байта `closes` плитки. В игре предмет с флажком
`DGX_GE_ITEM_INSIDE` обрезается, кроме обычного открытого пространства,
проёмом клетки под его ногами или соседа в той же строке, чей проём до неё
дотягивается. Редактор показывает проём синей рамкой (флажок Bodies, в
миниатюре — для `mod` 0, `variant` 0) и правит его в свойствах плитки
(Opening).

```json
"opening": {"dx": 32, "dy": 0, "w": 48, "h": "16 + 4 * min(q, 12) + lo"}
```

Кусок стоит базовой точкой в левом нижнем пикселе клетки, сдвинутой на
`dx`, `dy`, в слое сцены `layer` (имя слоя); `key` — для слоя с порядком
`key`. Обязательны `layer` и одно из: `set` + `image`, `by_mod`, `pick` +
`pictures`, `cycle`, `"draw": "fill"`. Остальное необязательно:

| Поле | Смысл |
| --- | --- |
| `set`, `image` | Одна картинка: кадр набора |
| `by_mod` | `[{set, image} \| null, ...]` — картинка по модификатору клетки (`mods` сетки): `mod` 0 — первая, 1 — вторая…, больше последней — последняя (ворота закрыты / открыты, вид зелья); `null` — при этом модификаторе куска нет. Дополнять список повторами не нужно |
| `pick`, `pictures` | Как `by_mod`, но номер картинки — выражение `pick`: картинка `pictures[round(pick)]`, номер прижат к 0…длина − 1; `null` в списке — куска нет |
| `cycle` | `[{set, image, ms}, ...]` — картинки идут по кругу по общему времени сцены, все клетки в такт; игра их не трогает (вода, лава) |
| `dx`, `dy` | Число или выражение на языке выражений `.anim` из `mod`, `variant` и полей набора плиток (`"-mod / 4"` — ворота поднимаются); выражение из одних чисел конвертер сворачивает |
| `around` | `{сторона: условие}` — кусок рисуется, только если соседи клетки такие, все условия вместе. Стороны: `up`, `down`, `left`, `right`, `up_left`, `up_right`, `down_left`, `down_right`. Условие: `"empty"`; имя плитки этого набора; список имён `["floor", "loose"]` (любая из них); `"solid_top"`, `"solid_left"`, `"solid_right"`, `"solid_bottom"`, `"solid_any"` — у соседа сплошная такая сторона (любая); `"not "` перед любым из них, кроме списка. За краем сетки сосед — что скажет игра (у PoP — соседние комнаты); редактор считает его пустым |
| `variant` | Кусок рисуется только в клетках, где вариант оформления (`variants` сетки, 32 бита) равен этому числу |
| `when` | Выражение из `mod`, `variant` и полей набора (со сравнениями и `and`, `or`, `not`): кусок рисуется только там, где оно не 0. `"mod > 0 and variant == 0"`. Постоянное не 0 — без проверки; постоянный 0 — ошибка (кусок не рисуется никогда) |
| `with` | `"self"` (нет поля — так же) или сторона, как в `around`: кусок кладётся, когда сетка кладёт клетку с этой стороны, среди её кусков. Место (`dx`, `dy` от своей клетки) и правила `around` — своей клетки. Край пола справа: `"with": "right"`, `dx` — ширина клетки |
| `step` | 0…255 — очередь среди кусков, кладущихся с клеткой, 0 первыми; нет поля — 0. В одной очереди — сначала свои куски клетки, потом пришедшие сверху, снизу, слева, справа, сверху-слева, сверху-справа, снизу-слева, снизу-справа, каждые в своём порядке |
| `draw` | `"normal"` (нет поля — так же), `"card"` — на прямоугольнике своего цвета размером с картинку, закрывающем то, что за ним, `"silhouette"` — форма картинки одним цветом, `"fill"` — без картинки, прямоугольник своего цвета размером `size` |
| `size` | Для `fill`: `[ширина, высота]`, левый нижний угол — в левом нижнем пикселе клетки, сдвинутом на `dx`, `dy` |
| `color` | Для `card`, `silhouette`, `fill`: `n` — цвет пикселей значения `n` набора самого куска, `[набор, n]` — другого набора; 0 — бумага кадра. `n` может быть выражением, как `dx`: `["walls", "f0 + 6"]` |

Пример: ворота — картинка по модификатору, поднимаются на четверть
модификатора, только если сверху не стена, а снизу стена или пол, и только
в клетках варианта 2:

```json
{ "layer": "back", "by_mod": [ { "set": "walls", "image": "door0.png" }, { "set": "walls", "image": "door1.png" } ],
  "dy": "-mod / 4", "around": { "up": "not wall", "down": ["wall", "floor"] }, "variant": 2 }
```

Список в `around` отрицать нельзя (`"not"` — только перед одним именем,
`empty` или `solid_*`): вместо этого дайте список остальных плиток.

Место оставлено для смещений границ `solid` и процедурных плиток (рисунок
от позиции клетки).

**Выход** (`exits`) — куда ведёт сцена: через край (`edge`: `left`,
`right`, `up`, `down`) — выход по стороне графа, без имени и входа; или по
имени (`name`, `edge` пуст; `zone` — имя зоны этой сцены, только подсказка,
где он) в сцену `scene`, к её входу `entry` (обязателен), с переходом
`transition`: `cut`, `fade`, `wipe`, `seamless` (сразу и как шёл: пришедшего
не заводят заново). Сцены с выходами — граф, как в Metal
Gear; комнаты, связанные краями, — частный случай. Подробно — «Граф сцен».

**Связь** (`links`) — что действует на что: `from` — клетка
`{grid, col, row}` или объект `{object: имя}` (персонаж или зона;
картинка и вход ничего не запускают), `to` — клетка (объект целью пока
нельзя: движок говорит события связей жизням клеток, а персонажа сцены,
которую не показывают, нет); `event` — событие пакета жизни клетки-цели
(пустая строка — то, которое шлёт источник), `value` — число
−32767…32767 в её параметр 0 перед событием или `null`. Связи есть только
у сцен карты графа. Для движка (`dgx_ge_links.h`, блоб DGLK карты) связи
группируются по источнику: источник называет свою первую связь, последняя
его помечена. Порядок — сцены карты по порядку документа, в сцене
источники в порядке их первого появления в списке связей, связи источника
подряд (в списке редактора они могут идти вперемешку — упаковщик их
собирает).

**Номера клеток карты** — сквозные: сцены карты по порядку документа,
сетки сцены по порядку, сетка по строкам, номер = `first` сетки + `row` ×
`cols` + `col`. Сетка 3×3 первой сцены — клетки 0…8, сетка 2×2 второй —
9…12. Сцена вне карт нумеруется сама по себе. В карте не больше 65535
клеток. Редактор показывает номера и первые связи источников в узле
**Maps** (таблица Names).

У входа (`entry`) ещё `arrive` — событие пакета тому, кто пришёл (пустая
строка — нет), и `fires` — чьи связи запустить по приходу: `{scene,
object}` или `{scene, grid, col, row}` — источник связей в сцене той же
карты, у которого есть связи, или `null`. Это первая связь источника в
блобе связей карты; вход запускает одну из первых 255.

У сцены: `map` — имя карты (пустая строка — сцена вне графа), `index` —
номер в карте 0…255, `kind` — `room` или `show`, `onEnter` — событие
правилам карты при входе (пустая строка — нет), `leave` — `{left, right,
up, down}`: событие правилам карты при уходе со сцены по стороне (пустая
строка — нет; сторона с событием без сцены рядом — выход с карты).

Редактор проверяет: имена, координаты и `factor` в 16 битах, от 1 до 8
слоёв, номера плиток в пределах набора, что выходы, входы, зоны, связи,
наборы, скрипты и параметры персонажей существуют. Кусок плитки в слое,
которого в сцене нет, — предупреждение.

### Сцены в пакете

Упаковщик (`add_sprites`) читает `screen` и
`scenes` из файла: каждая сцена — блоб `SCENE_<ИМЯ>` формата DGSC версии 2
(`include/dgx_ge_layout.h` движка; версию 1 движок не открывает): слои (`factor`, `order`), картинки
(`set`/`image`, x, y, `key`, `flip`, `clip`), зоны (`kind` — слово игры),
входы (x, y, `flip`), персонажи (набор с анимацией; `script` — пустая
строка: первый скрипт; x, y, `flip`; `params` по именам параметров
анимации), сетки (`tileset`, x, y, `cols`, `rows`, `cells`, `mods`,
`variants`; слоты набора плиток — в слои сцены по имени слоя куска; у
сетки ещё номер её первой клетки в карте), таблица источников связей
сцены (клетка, персонаж или зона и номер его первой связи). Движок
открывает такую сцену и раскладывает её (`dgx_ge_layout.h`: слои и картинки
в сцену игры, зона, вход, персонаж с запуском, сетка с установкой; клетка
по номеру — `dgx_ge_layout_cell_at`, первая связь источника —
`dgx_ge_layout_links_of`).

Связи карты — один блоб `<ГРАФ>_<КАРТА>_LINKS` (DGLK, в заголовке
`<PREFIX>_BLOB_<ГРАФ>_<КАРТА>_LINKS`), если у сцен карты есть связи.

Константы заголовка: `<PREFIX>_SCREEN_WIDTH`, `_SCREEN_HEIGHT`;
`<PREFIX>_SCENE_<СЦЕНА>_LAYER_`, `_PICTURE_`, `_ACTOR_`, `_ZONE_`,
`_ENTRY_`, `_GRID_<ИМЯ>` — номер в своём списке сцены (картинка без имени
— без константы); слова видов зон — `<PREFIX>_ZONE_<СЛОВО>`, по первому
появлению.

Упаковщик отказывает, а редактор показывает это ошибкой: персонаж набора
без анимации (или набора правил карты — он видом не становится), скрипта
или параметра, которого нет; клетки не `rows × cols`; номер плитки вне
набора; два слоя, два объекта одного вида или две сетки с одним именем в
заголовке; не 1…8 слоёв; число не в 16 битах
(место, `key`, `clip`, размер зоны, параметр персонажа), модификатор не
0…255; слои, картинки, зоны, входы и персонажи сцены больше 64 КБ; два
блоба пакета с одним именем (`SCENE_<ИМЯ>`, граф, диалог, анимация набора,
набор плиток, связи карты); связь из картинки или входа, связь в объект,
связь в клетку вне сетки, связи у сцены не из карты графа; `fires` входа
источника без связей или из сцены другой карты, первая связь `fires` не
меньше 255; больше 65535 клеток в карте. Объект неизвестного `type` упаковщик тоже не примет, а
редактор такой файл не открывает. Редактор строже в одном: имя объекта у него одно на всю
сцену, какого бы вида объект ни был.

## Стили диалогов

Поле `styles` — необязательный список стилей: как выглядит разговор.
Диалог называет стиль (`style talk`); стиль, которого нет в списке, —
стиль движка по умолчанию. Упаковщик (`add_sprites`) кладёт стили в блоб
`STYLES` (48 байт на стиль, `include/dgx_ge_talk_view.h`), имя — константа
`<PREFIX>_STYLE_<ИМЯ>`.

```json
"styles": [{
    "name": "talk",
    "frame": "fill",
    "place": [4, -4, -8, 44],
    "padding": [6, 4, 6, 4],
    "font": "TerminusTTFMedium12",
    "scale": [1, 1],
    "important": false,
    "scrollMs": 1200,
    "waitMs": 0,
    "borderWidth": 1,
    "colors": {"fill": [16, 16, 48], "border": [200, 200, 220], "text": [240, 240, 240],
               "bar": [64, 64, 140], "name": [255, 220, 120]}
}]
```

| Поле | Смысл; нет поля — значение движка |
| --- | --- |
| `name` | Имя стиля: его называет диалог |
| `frame` | `fill` — заливка `colors.fill` с каймой `colors.border` толщиной `borderWidth`; `picture` — картинка из девяти кусков (`picture` — `{set, image}`, `insets` — `[l, t, r, b]` неизменных углов, каждый не меньше 1, середина не меньше точки; упаковщик режет её на картинки `<СТИЛЬ>_FRAME_0…8` по строкам — их имена не должны совпадать с картинками наборов; под рамкой заливка `colors.fill`, углы как есть, края и середина повторяются от левого верхнего угла своего места; кусок двухцветной картинки — цветом `colors.border`; кайма не рисуется; 10 актёров сцены против 2 у заливки); `none` — без рамки. Нет — `fill` |
| `place` | `[x, y, w, h]` рамки на экране: `x`, `y` меньше 0 — от правого, нижнего края (`x = экран + x − w`); `w`, `h` 0 и меньше — экран минус столько. Нет — `[4, -4, -8, 44]` |
| `padding` | `[l, t, r, b]`: поле текста внутри рамки. Нет — `[6, 4, 6, 4]` |
| `font` | Шрифт DGX по имени функции (`TerminusTTFMedium12`, рукописный `font0ss`); упаковщик нумерует шрифты по первому появлению (`<PREFIX>_FONT_<ИМЯ>`, всего — `<PREFIX>_FONT_COUNT`), игра даёт таблицу в том же порядке. Нет — первый шрифт игры. У рукописного шрифта `scale` — высота строки в точках |
| `scale` | `[наибольший, наименьший]` целые масштабы шрифта: берётся наибольший, при котором текст влезает, не меньше наименьшего; ответы — при наименьшем. Нет — `[1, 1]` |
| `important` | Реплики важные, если диалог не скажет иначе: не влезшая показывается целиком прокруткой, неважная обрезается «...» |
| `scrollMs` | Прокрутка важной реплики: строка вверх каждые столько мс (0 — только кнопкой). Нет — 1200 |
| `waitMs` | Реплика без своего времени идёт дальше через столько мс; 0 — ждёт кнопку |
| `borderWidth` | Толщина каймы, точек. Нет — 1 |
| `appear` | `now` — реплика сразу; `letters` — по буквам, буква каждые `letterMs` мс (0…255, нет — 40). Буквы — символы строк раскладки, пробелы внутри строки тоже; пробел на переносе и `\n` — нет. Пока реплика появляется, прокрутка стоит; кнопка показывает её всю; время ожидания реплики идёт, когда она появилась. Нет — `now` |
| `portrait` | `none`, `left`, `right`: портрет говорящего (или выбирающего) — `face` его роли в диалоге (`roles guard GUARD "Стражник" face GUARD_FACE`) — в верхнем углу этой стороны внутри отступов, обрезанный по `portraitWidth` (0…255) и высоте поля; поле текста уже на `portraitWidth + padding.l`, слева — и сдвинуто; картинки контролов справа кончаются перед портретом. Свои цвета набора; двухцветная картинка — цветом `text`. Нет — `none` |
| `pen` | `hard`, `soft`: перо рукописного шрифта (DGX_FONT_HW) — мягкое пишет 15 оттенками между `fill` и `text`; у точечных шрифтов ничего не меняет. Нет — `hard` |
| `showName` | Имя говорящего (или выбирающего) — строкой над текстом цветом `colors.name`, при наименьшем масштабе; поле текста ниже на `yAdvance × наименьший масштаб`. Имя — имя роли в диалоге (`roles guard GUARD "Стражник"`) |
| `align` | `left`, `middle`, `right`: каждая строка текста (и имя, и ответы) в своём поле — слева, посередине (остаток ширины пополам, лишняя точка справа), справа. Остаток — от ширины поля, округлённой вверх до 8 точек, и ширины всей строки (с «...» обрезанной); появляющаяся строка стоит там, где будет целиком. Упаковщик кладёт в биты 1–2 последнего байта стиля (бит 0 — `showName`). Нет — `left` |
| `colors` | RGB: `fill`, `border`, `text`, `bar` (полоса под выбранным ответом), `name` (имя говорящего); игра добавляет их к цветам кадра |

Ответы идут списком, по строке на ответ, при наименьшем масштабе, не
обрезаются; список прокручивается за выбранным, полоса `bar` — внутри
рамки под его строкой. Поля, которых редактор ещё не знает, он сохраняет как есть.

Редактор показывает стиль на вкладке **Dialogs** точно как движок
(`Text.js` — раскладка, как `src/dgx_ge_text.c`; рамка и полоса — как
`src/dgx_ge_talk_view.c`). Шрифты для показа загружаются из исходников C
(`Text.readFont`, как `font2c/dgx_fonts.py json` из DGX) и в файл не входят.

## Палитры

Поле `palettes` — необязательный список `{name, colors}`: наборы цветов
без своих картинок (EGA игры, цвета стражников по уровням). Цвет `n`
палитры — `colors[n − 1]`, как цвета набора пакета для значений 1…n. Цвет
куска плитки `[ИМЯ, n]` называет палитру или набор картинок; у палитры и
набора не может быть одного имени, даже после перевода в имя заголовка
(`Ega` и `EGA` — одно). В палитре от 1 до 255 цветов.
Упаковщик (`add_sprites`) делает каждую палитру набором цветов
пакета (`add_set`) после наборов картинок и до плиток и стилей; заголовок
называет её `<PREFIX>_SET_<ИМЯ>`.

Редактор ещё показывает набор картинок в цветах палитры (Frames, «Preview
in»): номера цветов картинок те же, сами файлы не меняются; это
настройка просмотра, в файл разметки не идёт.

## Диалоги

Поле `dialogs` — необязательный список `{name, text}`: тексты диалогов на
языке диалогов движка (`tools/dgx_ge_dialog.py`: `dialog`, `roles`, `game`,
`style`, `pause`, `label`, `say`/`say!`, `choose` с ответами (ответ — с
контролом `control ВИД параметр` или с полем игры `field ИМЯ`), `tell`, `give`,
`goto`, `end`; реплика показывает до четырёх чисел `{параметр}` говорящего,
форма множественного числа — по первому; перевод (`.po`) показывает те же
`{имена}` в любом своём порядке (упаковщик хранит их как `{i}` — номер числа
в реплике), имя не из реплики — ошибка; `.po` и тексты диалогов читаются в
NFC, BOM пропускается; в условиях ответов можно называть
константы пакета — поле `constants`: `"Gamepad" if board & BOARD_PAD …`). `pause` — строка заголовка, одна
и без слов после неё: пока диалог открыт, игра стоит (мир, время, таймеры,
актёры), а у самого разговора время идёт; его `tell`, `give` и условия
приходятся на мгновение, где мир стоит (бит `DGX_GE_DIALOG_PAUSE` в байте
флагов блоба). Поле игры (`"Имя" field name -> back`) объявляет игра
вызовом упаковщика `Pack.add_field(name, size, keyboard=, letters=)`
(заголовок: `<PREFIX>_FIELD_<ИМЯ>`, `_SIZE`, `<PREFIX>_FIELD_COUNT`); в
файле редактора полей нет, поэтому имя поля редактор не проверяет —
незнакомое отвергнет упаковщик. В блобе такой ответ — контрол вида
`0xFFFE` (`DGX_GE_DIALOG_FIELD`) с номером поля; `activate` правит поле,
по окончании правки ответ ведёт на свою метку. Редактор хранит текст как есть; упаковщик читает диалоги из
файлов `dialogs/<имя>.dlg` рядом с JSON — их пишет в папку игры сам
редактор (без папки — кнопка ⭳ у диалога), как `.anim` наборов. Переводы — `po/<язык>.po` (gettext,
`msgctxt` — имя диалога); редактор загружает их только для проигрывания,
в файл они не входят.

## Игра целиком

Необязательные поля того, что игра даёт пакету помимо видов, сцен и
диалогов. Редактор правит их в узле **Game** и проверяет так же, как
упаковщик (`Game.js`). Упаковщик (`add_sprites`) читает их из
файла теми же вызовами `add_*`, что в таблице ниже. Времена везде — текст `500ms` или `2s`;
имена — `[A-Za-z_][A-Za-z0-9_]*`; события — имена событий любого набора
файла (события общие для пакета).

```json
"game": [{"name": "kinds", "value": 29}, {"name": "lives", "value": 30}],
"timers": [
    {"name": "clock", "every": "1s", "reset": "never", "event": "second", "start": "game"},
    {"name": "feather", "once": "18750ms", "reset": "map", "event": "", "start": ""},
    {"name": "button", "every": "500ms", "until": "10s", "reset": "scene", "event": "release", "start": ""}
],
"sounds": ["step", "sword"],
"shows": [{
    "name": "TITLE",
    "pictures": [{"picture": "TITLE_BACK", "x": 0, "y": 199, "layer": 0, "flip": false, "color": 0}],
    "actors": [{"name": "words", "kind": "TITLE_WORDS", "script": "", "x": 160, "y": 100, "layer": 1, "flip": false, "color": 15}],
    "cues": [{"at": "2170ms", "role": "words", "event": "next"}, {"at": "19100ms", "role": "end", "event": ""}]
}],
"chases": [{"kind": "GUARD", "sense": "always", "sides": ["left", "right", "up", "down"], "hearing": 0,
            "near": {"left": 32, "right": 33}, "steps": 0, "calm": ""}]
```

| Поле | Смысл | Упаковщик |
| --- | --- | --- |
| `game` | Список `{name, value}`: числа игры, 32-битные, в этом порядке; лежат в пакете (блоб GAME), заголовок называет их `<PREFIX>_GAME_<ИМЯ>`. В редакторе — **Numbers** | `add_game(**{name: value})` |
| `constants` | Объект `{имя: число}`: константы пакета — имена чисел, которые пишут тексты скриптов и условия ответов диалогов вместо чисел (`{"TICK_MS": 83, "TILE_FLOOR": 2}`); имена `[A-Za-z_][A-Za-z0-9_]*`, числа 32-битные. Числами их делает упаковщик при сборке; в пакет и в заголовок они не идут (это не `game`). Упаковщик даёт их до сборки анимаций (после `meets`). В редакторе — **Constants**; переименование меняет имя и в скриптах | `add_constants(**constants)` |
| `timers` | Список таймеров: `name`; ровно одно из `once` (сработать раз через столько) и `every` (каждые столько); `until` только с `every` (не дольше предела от старта, не короче периода); `reset` — `never`, `scene` или `map`; `event` — событие пакета владельцу при срабатывании или пустая строка; `start` — `game` (идёт с начала игры, владелец — игра) или пустая строка. Не больше 255 | `add_timer(name, once=, every=, until=, reset=, event=, start=)` |
| `sounds` | Список имён; номер звука — место в списке с 0 | `add_sound(name)` по порядку |
| `shows` | Список показов: `name` — имя блоба (не совпадает с именем набора); `pictures` — `{picture, x, y, layer, flip, color}`: имя картинки пакета, место базовой точки, слой 0…7, отражение, цвет однобитной картинки; `actors` — `{name, kind, script, x, y, layer, flip, color}`: роль (не `end`, уникальна), набор с анимацией, скрипт (пусто — первый), место; `cues` — `{at, role, event}`: время от начала, роль или `end`, событие пакета. Хотя бы одна реплика `end` | `add_show(name, pictures, actors, cues)`; `cues` как `(at, role, event)` |
| `crops` | Список `{name, set, image, x, y, width, height, originX, originY}`: часть картинки кадра `set/image` (от её левого верхнего угла) как своя картинка пакета `name` того же набора цветов, с базовой точкой `originX, originY` в пикселях вырезки | `add_crop(name, picture, x, y, width, height, origin)` |
| `chases` | Список `{kind, sense, sides, hearing, near, steps, calm}`: набор с анимацией (один раз); `sense` — `none`, `sight`, `hearing`, `always`; `sides` — подмножество `left`, `right`, `up`, `down`, `doors`; `hearing` — 16-битное; `near` — объект с ключами из `left`, `right`, `up`, `down` (нет ключа — где угодно); `steps` 0…255; `calm` — время до 65535 мс или пустая строка (никогда) | `add_chase(kind, sense=, sides=, hearing=, near=, steps=, calm=)` |

Пустые списки редактор пишет как `[]`; старые файлы без этих полей
читаются как пустые.

## Граф сцен

Необязательные поля графа сцен (`tools/dgx_ge_graph.py`, блоб DGSG версии 3):
`graph` и `maps`; остальное — поля сцен, выходов и входов (раздел «Сцены»).
Редактор правит их в узле **Maps** и в свойствах сцен, проверяет в
`Maps.js`. Упаковщик (`add_sprites`) строит из них `Graph` и
кладёт `add_graph`; правила карты — текст `<rules>.anim` рядом с файлом, а
набор, названный в `rules`, видом пакета не становится. Выход в сцену не из
карты он не примет. `fires` входа — номер первой связи источника в блобе
связей карты (см. «Сцены в пакете»).

```json
"graph": {"name": "WORLD", "start": {"scene": "level1", "entry": "start"}},
"maps": [
    {"name": "level1", "data": "LEVEL_1", "rules": "WORLD_LEVEL1_RULES", "number": 1,
     "exits": [{"name": "next", "scene": "level2", "entry": "start", "transition": "fade"}]},
    {"name": "title", "data": "TITLE", "rules": "", "exits": []}
]
```

| Поле | Смысл | Упаковщик |
| --- | --- | --- |
| `graph.name` | Имя графа — блоб пакета и префикс констант `<ИМЯ>_EXIT_*`, `_ENTRY_*`, `_MAP_*` | `Graph(name)` |
| `graph.start` | Сцена и её вход, с которых игра начинается | `g.start(scene, entry)` |
| `maps[].name` | Имя карты | `g.map(name, data, rules)` |
| `maps[].data` | Имя блоба данных карты: уровень (кладёт игра) или показ из `shows`; пустая строка — нет | `data=` |
| `maps[].rules` | Имя набора (вида) с анимацией — правила карты; пустая строка — нет. Его текст `.anim` — правила; `go ИМЯ` в нём пишется как `signal N` с номером имени выхода | `rules=` текст анимации |
| `maps[].number` | Номер, которым игра называет карту (строка уровня), 0 — никакого | `number=` |
| `maps[].exits` | Выходы карты: `{name, scene, entry, transition}` | `g.exit(map, name, scene, entry, transition)` |
| сцена с `map` | Узел графа: `g.scene(map, index, kind, onEnter)`; её выходы по сторонам — `g.side`, события ухода — `g.leave(scene, side, event)`, по имени — `g.exit(scene, name, to, entry, transition)`; входы — `g.entry(scene, name, x, y, left=flip, arrive, fires)` | |

Номера имён выходов и входов упаковщик даёт по первому появлению, и
редактор показывает их так же (таблица Names): карты по порядку; в карте
сцены по порядку документа, у сцены сначала входы (объекты по порядку),
потом именованные выходы по порядку; потом выходы карты. `fires` входа —
номер первой связи источника в блобе связей карты, по порядку, описанному
в «Сцены».

## Зеркалирование

Развёрнутый спрайт отражается вокруг базовой колонки, базовая линия не
меняется. Пиксель (x, y) переходит в (−x, y): столбец 0 остаётся на месте,
поэтому развёрнутый персонаж стоит там же, где стоял.

| Что | Как отражается |
| --- | --- |
| Пиксель, точка привязки | (x, y) → (−x, y) |
| Прямоугольник маски | `x` → −(x + width − 1), биты каждой строки в обратном порядке; `y`, `width`, `height` те же |
| Холст | `left` → −(left + width − 1) = 1 − left − width; `top`, `width`, `height` те же |
| Картинка | Её левый верхний пиксель (−origin.x, −origin.y) переходит в (origin.x − width + 1, −origin.y), столбцы в обратном порядке |

Например, маска `walk-1` занимает x от −3 до 3, отражённая — тоже от −3 до
3. Холст `walk` (x от −6 до 12) отражённый занимает x от −12 до 6.

## Что гарантирует редактор

Файл, сохранённый редактором:

- все координаты и размеры — целые числа, размеры не отрицательные;
- каждая маска кадра обрезана по своим пикселям, а пустая маска имеет
  вид `{"x": 0, "y": 0, "width": 0, "height": 0, "rows": []}`;
- в `rows` ровно `height` строк, в каждой ровно `ceil(width / 4)` цифр,
  цифры в нижнем регистре;
- холст набора охватывает базовую точку, картинку, маски и точки каждого
  кадра набора;
- маски кадров — только тех индексов, что описаны в `masks` файла;
- кадры набора упорядочены по имени файла.

Файл, исправленный вручную, может этого не соблюдать. Конвертеру стоит
проверять, что маски кадра описаны в `masks` файла и что `width` и `height`
кадра совпадают с размером PNG, и сообщать об ошибке, а не угадывать.

## Как прочитать: пример на Python

```python
import json


def read_sprites(path):
    with open(path, encoding='utf-8') as f:
        doc = json.load(f)
    if doc.get('format') != 'dgx-ge-sprites':
        raise ValueError('not a dgx-ge-sprites file')
    if doc.get('formatVersion', 0) > 1:
        raise ValueError('format version %s is unknown' % doc.get('formatVersion'))
    return doc


def mask_pixels(mask):
    """Pixels (x, y) of a mask, from the base point."""
    for r, row in enumerate(mask['rows']):
        for c in range(mask['width']):
            if (int(row[c // 4], 16) >> (3 - c % 4)) & 1:
                yield mask['x'] + c, mask['y'] + r


def frame_masks(sprite_set, frame, picture):
    """{index: set of pixels (x, y)} of a frame; picture is rows of palette indexes."""
    if frame['masks']:
        return {int(k): set(mask_pixels(m)) for k, m in frame['masks'].items()}
    if sprite_set.get('defaultMask') is None:
        return {}
    ox, oy = frame['origin']['x'], frame['origin']['y']
    return {sprite_set['defaultMask']: {(px - ox, py - oy)
                                        for py, line in enumerate(picture)
                                        for px, v in enumerate(line) if v}}
```

Для `examples/walk.json` это даёт 58 пикселей тела у `walk-1`, а у
`walk-3` — 71 пиксель тела и 5 пикселей клинка (индекс 2) с x от 7 до 10.

## Картинки

- На входе индексированные PNG (тип цвета 3), глубина 1, 2, 4 или 8 бит,
  без чересстрочности. Один файл — один кадр.
- Индекс 0 прозрачен всегда, что бы ни было записано в самом PNG (`tRNS`).
  Все прочие индексы непрозрачны.
- Пиксели картинки меняют только сдвиг выделенной области (инструмент
  Move), рисование (Pencil, Fill) и правка палитры; новый пустой кадр
  редактор делает сам (New frame). Изменённая картинка сохраняется в PNG
  того же размера, со своей палитрой (новый цвет может увеличить глубину:
  1, 2, 4, 8 бит) и с теми же прочими блоками исходного файла (`tRNS`,
  `pHYs`...). Формат разметки от этого не меняется.

## Чего в файле нет

- Картинок: кадр ссылается на PNG по имени; упаковщик ищет его рядом с
  JSON, в `<НАБОР>/<файл>` или прямо там (или в каталоге, который ему
  назвали).
- Палитр картинок и пикселей: они в PNG (поле `palettes` — палитры без
  картинок).
- Байт-кода анимаций: его делает ассемблер движка из текста `.anim`.
- Видимости масок, масштаба и прочего вида редактора: это хранится только в
  браузере (`localStorage`).

## Где это в коде

| Файл | Что там |
| --- | --- |
| `Store.js` | `SpriteFormat` (имя и версия формата), `MaskLimit`, `readSprites` — проверка загружаемого файла, `frameExtent` — что кадр занимает на холсте |
| `Mask.js` | Кодирование маски в `rows` и обратно, маска по умолчанию (`fromPicture`) |

| `PngIndexed.js` | Чтение индексов пикселей из PNG и запись PNG |
| `Scene.js` | Сцены: чтение и проверка полей `screen`, `tilesets`, `scenes`, имена-константы |
| `Anim.js` | Анимации: разбор и запись текста `.anim`, матрица из правил с конфликтами, проверки, чтение поля `animation`, проигрыватель, повторяющий исполнитель движка |
| `Game.js` | Игра целиком: чтение и проверка полей `game`, `constants`, `timers`, `sounds`, `shows`, `chases`, `crops`, их редактор |

| `Problems.js` | Все проверки файла в одном списке, для узла Problems |
